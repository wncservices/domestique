# LLM jobs (6b) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add three local-model jobs:
- an explanation of the morning's automatic changes (Today page);
- a reading of the check-in note that the rider confirms with a tap;
- a Monday summary of last week (Plan page card).

**Architecture:**
- Three job files in `internal/llm`, built on 6a's `Complete`.
- One `llm_notes` table for stored text.
- A background step after the morning `AutoScheduleTick`, outside its lock.
- Two API endpoints and three UI pieces.

**Tech Stack:** Go stdlib, OpenTelemetry metrics (existing), Vue 3 / Nuxt UI.

**Spec:** `docs/superpowers/specs/2026-10-26-llm-jobs-design.md`

## Global Constraints

- **Jobs:** `explain_changes`, `understand_checkin` and `weekly_summary`.
  - Each is a `llm.Job` constant, an entry in `llm.Jobs` and in `config.LLMJobNames`, and can be switched off via `llm.jobs`.
- **Output limits:**

  | Job | Output | Text limit | `max_tokens` |
  |---|---|---|---|
  | `explain_changes` | `{text}` | 1–3 sentences, ≤ 300 runes | 300 |
  | `understand_checkin` | `{legs, sleep, mood, life_event}` | — | 250 |
  | `weekly_summary` | `{text}` | ≤ 5 sentences, ≤ 700 runes | 450 |

- **Number rule:** "No invented numbers". Every number in `explain_changes` or `weekly_summary` text must appear in that call's input.
- **Check-in reading fields:**
  - `legs`, `sleep` and `mood` are each 1–5 or null.
  - `life_event` is null or `{kind: illness|travel, start_date, end_date, option}`.
    - `option` is `no_bike`/`gym` for travel, `mild`/`proper` for illness, or null.
    - Dates are `YYYY-MM-DD`, with start ≤ end, start ≥ today and end ≤ today + 60.
- **Storage:**
  - `llm_notes(rider, kind, day, text, created_at)`, unique `(rider, kind, day)`.
  - `kind` is `changes` or `weekly`.
  - Registered in `riderTables`.
  - A claimed row has empty text and reads as absent.
  - Rows are pruned once older than 60 days.
- **Background step:**
  - Runs after `AutoScheduleTick` finishes, outside its lock, under its own advisory lock `domestique:llm-notes`.
  - Runs only in the first sync slot (`inMorningSlot`), with auto-schedule on.
  - Covers riders with a goal.
- **Privacy:**
  - The note, the prompts and the model's text never appear in a log, span or metric.
  - Logs carry counts only.
  - The morning email is unchanged.
- Never commit `.superpowers/`. `gofmt` and `go vet` clean. No new dependency.

## Review Focus

1. **A week with no ledger row or no fitness snapshot.** The weekly summary's input leaves those figures out; it never sends zeros. A week with nothing at all writes no summary. Test in Task 3: `TestWeeklySummaryOmitsUnknownFigures`.
2. **The model paraphrases a number** ("about twenty minutes" is fine, but "25 min" when the input says 20 is not). `numbersIn` must catch digits, including decimals with a comma (Dutch `1,5`). Test in Task 1: `TestNumbersInFindsDutchDecimals`.
3. **The check-in is saved, but the reading fails or times out.** The saved check-in stays as it is, and the card shows one quiet line. Test in Task 4 (the browser check) and Task 3: `TestUnderstandFailureLeavesCheckInAlone`.
4. **Two replicas run the morning step at once.** Only one model call is made per rider, kind and day, through `ClaimLLMNote`. Test in Task 3: `TestLLMNotesRunOnce`.
5. **A rider renamed or merged after notes exist.** The notes follow the rider, and on merge the target's row wins. These are covered by the registry tests in Task 2.

**Interfaces (produces):**

```go
const (
	JobExplainChanges    Job = "explain_changes"
	JobUnderstandCheckIn Job = "understand_checkin"
	JobWeeklySummary     Job = "weekly_summary"
)
func numbersIn(text string) []string // digits with optional . or , decimals, normalised to "." ("1,5" -> "1.5")

type Change struct{ Title, Workout, Date string; Facts []why.Fact }
func (c *Client) ExplainChanges(ctx context.Context, today string, changes []Change) (string, error)

type CheckInReading struct {
	Legs, Sleep, Mood int        // 0 = not read from the note
	LifeEvent         *LifeEventReading
}
type LifeEventReading struct{ Kind, StartDate, EndDate, Option string }
func (c *Client) UnderstandCheckIn(ctx context.Context, today string, note string) (CheckInReading, error)

type WeekFigures struct {
	WeekStart, Phase                                string
	TargetTSS, RiddenTSS, DebtTSS, ForgivenTSS      *float64 // nil = unknown, left out of the prompt
	Done, Partial, Missed                           *int
	CTLStart, CTLEnd                                *float64
}
func (c *Client) WeeklySummary(ctx context.Context, w WeekFigures) (string, error)
```

- **Validators.**
  - The text jobs check: the text is non-empty, within the rune limit and sentence count (sentences split on `.!?`), and every element of `numbersIn(text)` appears in `numbersIn(prompt input)`.
  - `UnderstandCheckIn` checks the constraints above. The prompt lists today and the next 14 days with weekday names.
  - A failed check retries through `Complete`'s validate. A second failure returns `ErrInvalid`.

### Task 3: Background step and API

**Files:**
- Create:
  - `apps/api/internal/api/llmnotes.go`, holding `runLLMNotes`, `weekFigures` and the handlers.
  - `apps/api/internal/api/llmnotes_test.go`.
- Modify:
  - `apps/api/internal/api/autoschedule.go`: call `s.runLLMNotes(ctx)` after `AutoScheduleTick` returns, in the loop and wherever else the tick is run on schedule. It must not run inside `withDBLock(autoScheduleLockKey)`.
  - `server.go`: register the routes, and add the three new `llmJobs` fields (`explainChanges`, `understandCheckin`, `weeklySummary`).

**Interfaces:**
- Consumes Task 1's jobs and Task 2's store.
- Produces `GET /api/training/notes` with the response `{changes: {day, text} | null, weekly: {weekStart, text} | null}`.
- Produces `POST /api/training/checkin/understand` with the response `{legs, sleep, mood, lifeEvent: {kind, startDate, endDate, option} | null}`. A score of 0 means "not read".
- **`runLLMNotes` for each rider with a goal:**
  - Takes the advisory lock `domestique:llm-notes` and skips if it is held.
  - **`changes`:** when `AdjustmentsOnDay(today)` returns at least one row and the claim wins, it calls `ExplainChanges`. On an error, or when the job is off, it saves the fallback: the de-duplicated `why.Title`s, each ending in ".", joined with a space.
  - **`weekly`:** on Mondays, when the claim for last Monday wins, it calls `WeeklySummary` with `weekFigures(rider, lastMonday)`, built from the ledger row, compliance over that week, and fitness snapshots at both ends. Each piece is nil when missing. On an error, or when the job is off, it saves nothing.
  - **Every run:** it calls `PruneLLMNotes(today - 60 days)`.
  - **Logs:** counts only.
- **`understand` handler:**
  - It reads the note with `GetCheckIn(rider, localToday)` and returns 404 when the note is empty.
  - It returns 412 with a Warn when the job is off.
  - It goes through `rateLimitNarration`.
  - It maps `ErrInvalid`, `ErrTimeout` and transport errors to 502 with "Couldn't read the note this time."
  - It stores nothing.
