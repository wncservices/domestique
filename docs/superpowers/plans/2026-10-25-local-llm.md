# Local LLM (6a) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move the four narration features (plan explanation, goal and profile proposals, plan edits) from Anthropic to the lab's own model behind agentgateway, and remove the Anthropic client.

**Architecture:**
- A new `internal/llm` package holds one OpenAI-compatible client with JSON-schema output, a retry, a timeout and a result hook.
- The four jobs are ported into it with the same exported names and types as `internal/narration`, so the handlers swap one field.
- Config lives in `domestique.yaml` (`llm:`) and the key in `DOMESTIQUE_LLM_API_KEY`.

**Tech Stack:** Go stdlib (`net/http`, `encoding/json`), OpenTelemetry metrics (existing pattern), Vue 3 / Nuxt UI.

**Spec:** `docs/superpowers/specs/2026-10-25-local-llm-design.md`

## Global Constraints

- **Endpoint:** `POST {base_url}/chat/completions`.
  - Request body: `model`, `messages` (`system`, `user`), `temperature: 0.2`, `max_tokens`, and `response_format: {"type":"json_schema","json_schema":{"name":<job>,"strict":true,"schema":…}}`.
  - Send `Authorization: Bearer <key>` only when the key is non-empty. Never send an `Origin` header.
- **Jobs and `max_tokens`:**

  | Job | `max_tokens` |
  |---|---|
  | `explain_plan` | 200 |
  | `propose_profile` | 250 |
  | `propose_goal` | 250 |
  | `plan_edits` | 400 |

- **Timeout:** 120 s per call (`context.WithTimeout`, covering every attempt). **One retry** on unparseable or validator-rejected output, then `llm.ErrInvalid`.
- **Errors:**
  - Transport: `http.Client{Transport: telemetry.OutboundTransport(http.DefaultTransport)}` and `http.NewRequestWithContext` with the caller's ctx.
  - Unwrap `*url.Error` (keep `.Err`).
  - A non-200 response yields an error naming the status only; the body is never echoed.
- **Metric:** `domestique_llm_requests_total{job, result}`, where result is one of `ok`, `invalid`, `error`, `timeout`. It has no rider label.
- **Privacy:** prompts, outputs and the rider's sentence or note are never logged or put in a span. A log line carries the job and an outcome word.
- **Config** (`domestique.yaml`):
  - `llm.base_url`: empty means every job is off.
  - `llm.model`: required when `base_url` is set.
  - `llm.jobs`: an optional map from the job names above to bool. Every job defaults to true.
  - The env var `DOMESTIQUE_LLM_API_KEY` is optional.
- `ANTHROPIC_API_KEY` is no longer read anywhere. `internal/narration` is deleted.
- **Handler contracts are unchanged.**
  - The route, request and response shapes stay the same.
  - A job that is off gives a 412 with a Warn.
  - A transport failure or `ErrInvalid` gives a 502.
  - The limiter's 429 stays.
- No new Go dependency. `gofmt` and `go vet` clean. Never commit `.superpowers/`.

## Review Focus

1. **A model that answers with prose or fenced JSON despite the schema** (a gateway or server that ignores `response_format`). Expect one retry, then a 502. It must never fall through as a half-parsed proposal. Test in Task 1: `TestNonJSONReplyRetriesThenInvalid`.
2. **Cold model load after an idle unload, where the first call takes about 60 s.** It must succeed within the 120 s budget. A single budget covers both attempts, so a slow first answer leaves less time for a retry and never more than 120 s in total. Test in Task 1: `TestTimeoutCoversBothAttempts`, which uses a short test timeout through an unexported field.
3. **A job switched off in config while the others stay on.**
   - Its endpoint returns 412.
   - `/api/me` shows that job false and `narrationEnabled` true.
   - The UI hides only that button.
   - Tests in Task 3 (`TestASwitchedOffJobIs412`) and Task 4.
4. **The gateway refusing a request (429 rate limit, 404 `model_not_found`).** Expect a 502 with no body echoed, and a metric result of `error`. Test in Task 1: `TestNon200EchoesNoBody`.
5. **A rider's Dutch note.** The prompt must not force English output fields such as enum values. Covered by the eval set's Dutch cases in Task 5. Enum values (`mon`…`sun`, `A`/`B`/`C`, `cycling`/`running`) are fixed in the schema `enum`, so a translated value cannot pass.

- Produces:

```go
// config
type LLMConfig struct {
	BaseURL string          `yaml:"base_url,omitempty"`
	Model   string          `yaml:"model,omitempty"`
	Jobs    map[string]bool `yaml:"jobs,omitempty"`
}

// llm
type Job string
const (
	JobExplainPlan    Job = "explain_plan"
	JobProposeProfile Job = "propose_profile"
	JobProposeGoal    Job = "propose_goal"
	JobPlanEdits      Job = "plan_edits"
)
var Jobs = []Job{JobExplainPlan, JobProposeProfile, JobProposeGoal, JobPlanEdits}
var ErrInvalid = errors.New("llm: the model's answer did not pass validation")
var ErrTimeout = errors.New("llm: the model did not answer in time")

type Client struct { /* baseURL, model, apiKey, jobs, httpClient, timeout, OnResult */ }
func New(cfg config.LLMConfig, apiKey string) *Client           // nil when cfg.BaseURL == ""
func (c *Client) Enabled(j Job) bool                             // nil-safe: false on a nil client
// OnResult, if set, is called once per Complete with result "ok"|"invalid"|"error"|"timeout".
func (c *Client) SetOnResult(f func(job Job, result string))
// Complete sends system+user with the schema, decodes the answer into out (DisallowUnknownFields),
// runs validate(out) and retries once on a decode or validate error. validate may be nil.
func (c *Client) Complete(ctx context.Context, j Job, system, user string, schema map[string]any, maxTokens int, out any, validate func() error) error
```

- [ ] **Step 1: Write the failing tests** in `client_test.go`. Each uses an `httptest` server that records the request and replies with `{"choices":[{"message":{"content":"<json>"}}]}`:

    - there is no `Origin` header;
    - `Authorization` is absent with key `""`, and is `Bearer k` with key `"k"`.
  - `TestDecodesIntoOut`: content `{"text":"hi"}` decodes into `struct{Text string}`, and OnResult reports `ok`.
  - `TestNonJSONReplyRetriesThenInvalid`: content "Sure! ```json…```" twice. Expect exactly 2 requests, an error that `errors.Is(ErrInvalid)`, and OnResult `invalid`.
  - `TestValidatorRejectionRetriesOnce`: validate fails the first time and passes the second. Expect 2 requests, nil error and `ok`.

### Task 2: Port the four jobs into `internal/llm`

**Files:**
- Create: `apps/api/internal/llm/explain.go`, `profile.go`, `goal.go`, `planedits.go`, and tests `explain_test.go`, `profile_test.go`, `goal_test.go`, `planedits_test.go`
- Read (source to port, do not modify): `apps/api/internal/narration/narration.go`, `planedits.go` and their tests

**Interfaces:**
- Consumes: Task 1's `Complete`, `Job*` and `ErrInvalid`.
- Produces the same exported names, fields and JSON tags as `narration`, so Task 3 only swaps the package:

```go
func (c *Client) ExplainPlan(ctx context.Context, goal workout.Goal, plan periodization.Plan) (string, error)
type ProfileChangeProposal struct{ /* identical to narration's */ }
func (c *Client) ProposeProfileChange(ctx context.Context, note string, profile workout.RiderProfile) (ProfileChangeProposal, error)
type GoalProposal struct{ /* identical */ }
func (c *Client) ProposeGoal(ctx context.Context, note string, today time.Time) (GoalProposal, error)
type Capabilities, PlanView, ViewDay, ViewSession, Intent, PlanEdits // identical
var ErrRejected // identical meaning: the model refused or answered outside the capabilities
func (c *Client) ProposePlanEdits(ctx context.Context, text string, view PlanView) (PlanEdits, error)
```

- **Port each job:**
  - Move its prompt-building function into the system message (instructions) and the user message (the note, goal, plan view).
  - Keep the facts each prompt includes today. Remove any "reply with JSON only / no fences" wording, since the schema enforces that.
  - Each job has a schema:
    - `explain_plan` is `{text: string, maxLength 600}`.
    - Profile and goal schemas mirror today's parsed fields, with `enum` for days (`mon`…`sun`), priority (`A`,`B`,`C`) and sport (`cycling`,`running`).
    - `plan_edits` is `{refused: boolean, intents: [...]}`, built from `Capabilities` exactly as `toolSchema` builds the tool's `input_schema`. The model replies `{"refused":true}` or with intents.
  - Today's post-parse rules become the `validate` func, with the same limits:
    - hours in (0, 12];
    - days limited to mon..sun;
    - goal date after today, distance ≤ 3000 km, elevation ≤ 60000 m, name cut to 80 chars;
    - at most 5 intents, types limited by `Capabilities`.
  - Two rules stay as they are:
    - Profile proposals keep today's fallback to the current profile for an out-of-range field. A field that is out of range is corrected, not retried. Only an undecodable answer retries.
    - A goal with an empty name is `ErrInvalid` after the retry, matching today's rejection.
  - `ExplainPlan` returns the trimmed text, and an empty text counts as invalid.

  - `TestRefusedIsErrRejected`: `{"refused":true}` gives `errors.Is(err, ErrRejected)`, after one request (no retry).
  - `TestEnumsAreInTheSchema`: the profile schema's day `enum` is exactly mon..sun, and the goal schema's priority `enum` is exactly A, B, C.
  - `TestPromptsCarryTheNote`: the user message contains the note. The system message contains no rider note.
- [ ] **Step 2: Run them and confirm they fail.**
- [ ] **Step 3: Implement.**
- [ ] **Step 4: Run them and confirm they pass.** `go test ./apps/api/internal/llm/ -count=1`
